API REST

Os três modos documentados em Technoworks.com.br/apidoc, abstraídos em uma única camada de serviço.

  • GET/apiLista todos os itens de estoque.
  • POST/apiCria um item. Corpo JSON com id, titulo, descricao, preco.
  • PUT/api/{id}Atualiza o item identificado pelo id.
  • DELETE/api/{id}Remove o documento do banco NoSQL.
  • GET/rest/{colecao}Lê uma coleção livre, ex.: movimentacoes.
  • POST/rest/{colecao}Insere documento com atributos dinâmicos (schema-less).
  • PUT/rest/{colecao}/{id}Atualiza o documento pelo id indexador.
  • DELETE/rest/{colecao}/{id}Remove o documento da coleção livre.
  • GET/easy?action=insert&id=…&titulo=…Insere via query string.
  • GET/easy?action=listConsulta todos os registros.
  • GET/easy?action=update&id=…Atualiza via query string.
  • GET/easy?action=delete&id=…Remove via query string.
POST /api — criação de item de estoque 
const BASE_URL = "https://technoworks.com.br/apidoc";

async function criarItemRest(item) {
  if (!item.id) throw new Error("O campo ID é obrigatório para persistência.");
  const r = await fetch(`${BASE_URL}/api`, {
    method: "POST",
    headers: { "Content-Type": "application/json", "Accept": "application/json" },
    body: JSON.stringify({
      id: item.id,
      titulo: item.titulo,
      descricao: item.descricao,
      preco: Number(item.preco),
      quantidade: Number(item.quantidade),
      estoque_minimo: Number(item.estoque_minimo),
      deposito: item.deposito
    })
  });
  if (!r.ok) throw new Error(`Erro HTTP: ${r.status}`);
  return await r.json();
}

Arquitetura distribuída

Camadas logicamente separadas: apresentação independente da persistência remota.

Requisito 1

Paradigma Web Service

Arquitetura orientada a recursos sobre HTTP/HTTPS. Nenhuma dependência de plataforma: Windows, Linux, macOS, Android ou iOS consomem o mesmo serviço.

Requisito 2

Front-End web

HTML5, CSS3 e JavaScript (ES6+) em página única, com consumo assíncrono via Fetch API e atualização dinâmica sem recarregar.

Requisito 3

Banco NoSQL

Orientado a documentos, sem esquema rígido — serialização direta de objetos JSON e escalabilidade horizontal.

Requisito 4

REST + JSON

Comunicação stateless com os métodos padrão GET, POST, PUT e DELETE e payloads leves em JSON.

Requisito 5

Chave id obrigatória

Chave primária distribuída: unicidade de registro, idempotência nas consultas e integridade nas alterações e exclusões.

Requisitos 6 e 7

Estrutura modular

Separação estrita entre visualização e serviço de comunicação, apta à migração para React ou TypeScript.

Integridade sob concorrência

A operação de saída é validada antes da gravação, e o saldo é recalculado a partir do histórico persistido — nunca da última leitura feita pelo cliente. Assim, duas saídas simultâneas do mesmo id não geram saldo negativo nem leitura desatualizada, e toda movimentação permanece rastreável até o documento de origem.
